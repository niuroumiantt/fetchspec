定位

六个采集队里的「产品与技术资料」队：按 inresearch 的目标行，从厂商官网取回官方产品规格，保留原件与原表，整理成可比较的参数，打包交付并拿回回执。收到不等于采用，研究事实由 inresearch 判断。

不给什么：翻译、研究结论、目标表状态、全站 URL 清单；新闻、财报、研报、报价、统计归其他队（inews、fetchfilings、fetchreports、fetchquotes、fetchstat）。

段命令做什么

listquery candidate products by company/name/kind
exportexport original cells and product map
bindexplicitly bind reviewed products to demand; no fuzzy inference
map-fieldrecord a reviewed comparison key without altering the raw cell
④ 输出packagebuild immutable v2 package from current bindings
receiptverify receiver acknowledgement against local package
assignmentsexport inresearch deliveries-import input from a validated receipt
author-proposalexport review proposal; never modifies author checkout
catalogexport structured candidate catalog; NVIDIA schema remains receiver compatible
运维status

所有命令：PYTHONPATH=src python3 -m fetchspec.pipeline [--root 数据根] <命令>

交付

项内容
包v2.0：manifest.json + SHA256SUMS + files/
每项带target_ids、part_ids、来源与语言、版本关系、产品身份、厂商原表、人审过的参数观测（值为厂商原文）
接收inresearch manage.py fetchspec-receive 逐文件验 SHA256 与契约，回执 JSON
登记assignments 生成每目标行一条的登记；作者 checkout 跑 deliveries import，走 PR 与审阅
不写Fetchspec 不写 inresearch 的 Git，不改目标表状态
